หมวดที่ 1: สถาปัตยกรรม Container ไฟล์ของเกม (FAFULLFS Format)
================================================================================

เกมใช้ Container รหัส 'FAFULLFS' ในการแพ็กไฟล์หลัก 2 ไฟล์:
  1. data.dat (ขนาดประมาณ 375 MB): เก็บ Database (.dat), สคริปต์ (.lub), เท็กซ์เจอร์
  2. data/misc_1_00.dat (ขนาด 166,815,977 bytes): เก็บไฟล์ฟอนต์และภาพแผนที่ตกปลา

โครงสร้างไบนารีของ FAFULLFS:
--------------------------------------------------------------------------------
[1. Header (48 Bytes)]
  - Offset 0x00 (8 bytes): Magic String 'FAFULLFS'
  - Offset 0x08 (uint32):  จำนวนไฟล์ทั้งหมด (File Count)
  - Offset 0x0C (uint32):  Unknown (ค่าคงที่ของเอนจิน เช่น 2117292)
  - Offset 0x10 (uint64):  Offset ตำแหน่งเริ่มต้นของ String Table
  - Offset 0x18 (uint64):  ขนาดของ String Table (ความยาวรวมของชื่อไฟล์)
  - Offset 0x20 (uint64):  Offset ตำแหน่งเริ่มต้นของ TOC (Table of Contents)
  - Offset 0x28 (uint64):  Reserved / Padding (0)
  *หมายเหตุ: หลัง Header 48 ไบต์ จะต้องมี Padding 0x00 ไปจนถึง Offset 0x200 (512 ไบต์)

[2. Payload Data (เนื้อไฟล์แต่ละไฟล์)]
  - ไฟล์แรกจะเริ่มที่ Offset 0x00000200 (512 bytes) เสมอ
  - ทุกไฟล์ต้องจัดเรียงตาม Sector Alignment ขนาด 512 ไบต์:
      new_offset = (current_offset + 511) & ~511; (หรือ offset % 512 == 0)
  - ช่องว่างระหว่างไฟล์จะถูกเติมด้วย 0x00 (Slack Bytes)

[3. TOC Table (Table of Contents)]
  - อยู่ที่ Offset ที่ระบุไว้ใน Header (TOC Offset)
  - ประกอบด้วย Record ของแต่ละไฟล์ เรียงติดต่อกัน ขนาด Record ละ 48 Bytes:
      * Offset +0x00 (uint64): File Path Hash (64-bit Murmur/FNV Hash)
      * Offset +0x08 (uint64): Relative Name Offset ใน String Table
      * Offset +0x10 (uint64): Reserved (0)
      * Offset +0x18 (uint64): ขนาดจริงของไฟล์ (File Size ในหน่วยไบต์)
      * Offset +0x20 (uint64): ตำแหน่ง Offset เริ่มต้นของไฟล์ใน Container
      * Offset +0x28 (uint64): Flags ประจำไฟล์
  *** กฎเหล็กของ TOC: ทุก Entry ใน TOC ต้องถูกเรียงลำดับตาม 'File Path Hash'
      จากน้อยไปหามาก (Ascending Order) เสมอ เพราะเอนจินเกมใช้ Binary Search ค้นหาไฟล์! ***

[4. String Table]
  - อยู่ถัดจาก TOC Table พอดี: str_tbl_offset = toc_offset + (files * 48)
  - เก็บ Path ชื่อไฟล์ทั้งหมด คั่นด้วย \x00 (Null-terminated ASCII/UTF-8)
  - ตัวอย่าง: "data/database/talk.dat\x00data/database/item.dat\x00"

*** เงื่อนไขพิเศษของ misc_1_00.dat (Font Container):
  - ตัวเกมบน Steam มีการตรวจสอบขนาดไฟล์ misc_1_00.dat ให้คงที่
  - ขนาดไฟล์ต้องเท่ากับ 166,815,977 bytes เป๊ะทุกไบต์
  - ตำแหน่ง TOC Offset ต้องล็อกไว้ที่ 166,814,720 (0x09F16400)
  - หากไฟล์ฟอนต์ที่แก้ใหม่มีขนาดเล็กลง ให้เติม 0x00 (Slack Padding) ด้านหน้า TOC 
    เพื่อให้ TOC Offset และขนาดรวมของไฟล์เท่าเดิม 100%

หมวดที่ 2: โครงสร้างไฟล์ Database (.dat) ภายในโฟลเดอร์ data/database/
================================================================================

ไฟล์ Database ทั้ง 36 ตัว (เช่น item.dat, talk.dat, tips.dat, string.dat) 
ถูกออกแบบเป็น Binary Structured Database:

1. Header ของ .dat:
   - เก็บจำนวนแถว (Record Count) และ Header Metadata
   - มี Pointer ชี้ไปยัง Data Block และ String Table ท้ายไฟล์

2. โครงสร้างหลายภาษา (Multilingual Array):
   - ข้อความที่แสดงในเกมจะถูกเก็บเป็น Array ของภาษาต่างๆ ตามลำดับดังนี้:
       Index 0 = ภาษาญี่ปุ่น (Japanese - JP)
       Index 1 = ภาษาอังกฤษ (English - EN)
       Index 2 = ภาษาฝรั่งเศส (French - FR)
       Index 3 = ภาษาเยอรมัน/สเปน (DE/ES)
       Index 4 = ภาษาจีนตัวเต็ม (Traditional Chinese - TC)
       Index 5 = ภาษาเกาหลี (Korean - KR)
       Index 6 = ภาษาจีนตัวย่อ (Simplified Chinese - SC)
   - พฤติกรรมของเอนจินเกม:
     * เมื่อผู้เล่นเลือกภาษาญี่ปุ่นใน Option -> เกมจะดึงข้อความจาก Index 0 (และใช้ฟอนต์ KiwiMaru)
     * เมื่อผู้เล่นเลือกภาษาอังกฤษใน Option -> เกมจะดึงข้อความจาก Index 1 (และใช้ฟอนต์ Lora)
   - สคริปต์แปลไทยที่ผ่านมา: ฉีดคำแปลไทยลงใน Index 0 (ญี่ปุ่น) และ/หรือ Index 1 (อังกฤษ) 
     เพื่อให้ข้อความไทยแสดงผลทันทีตามภาษาที่ผู้เล่นเลือก

3. String Table ใน .dat:
   - แต่ละ Record จะเก็บ Offset Pointer ที่ชี้ไปยังตำแหน่งเริ่มต้นของข้อความ
   - ทุกข้อความต้องปิดท้ายด้วย \x00 (Null Terminator) เสมอ
   - หากความยาวของข้อความแปลไทยยาวกว่าข้อความเดิม:
     * ต้องสร้าง String Pool ใหม่ท้ายไฟล์
     * และอัปเดต Pointer ใน Record Table ให้ชี้ไปยังตำแหน่ง Offset ใหม่อย่างแม่นยำ

หมวดที่ 3: เช็กลิสต์การตรวจความถูกต้อง (Programmer Verification Checklist)
================================================================================

โปรแกรมเมอร์กรุณาตรวจสอบตามรายการเหล่านี้ก่อนและหลังการประกอบไฟล์:

[✓ Checklist 1: ตรวจสอบแท็กคำสั่ง (Control Tags Integrity) - สำคัญที่สุด!]
  - ในไฟล์ tips.dat, talk.dat, string.dat มีแท็กเรียกใช้ไอคอนจอยสติ๊ก/ปุ่มคีย์บอร์ด
    เช่น: <cmd CMD_UNIT_MOVE_STICK -offsetY -5>
  - กฎเหล็ก: "ห้ามตัดช่องว่าง (Space) ภายในแท็ก <cmd ...> ออกเด็ดขาด"
    * ผิด: <cmdCMD_UNIT_MOVE_STICK-offsetY-5>  (เอนจินจะไม่รู้จักคำสั่ง ไอคอนจะหายทันที!)
    * ถูก: <cmd CMD_UNIT_MOVE_STICK -offsetY -5>
  - ตรวจสอบแท็กสี: <color 255 200 100>...</color> ต้องมีแท็กปิดครบ
  - สามารถรันสคริปต์ตรวจสอบแท็กอัตโนมัติได้จาก:
    00_เครื่องมือและสคริปต์ตรวจสอบ\validate_tags.py

[✓ Checklist 2: ตรวจสอบการแปลงรหัสฟอนต์ PUA (Private Use Area)]
  - ฟอนต์ภาษาไทยของเกมนี้ไม่รองรับ OpenType Shaping/HarfBuzz
  - เพื่อแก้ปัญหาสระลอย/สระจม วรรณยุกต์จึงถูกเลื่อนตำแหน่งไว้ที่รหัส PUA (U+F000 - U+F89F)
  - โปรแกรมเมอร์ต้องใช้ตาราง Mapping.json ที่แนบไว้ แปลงข้อความภาษาไทยธรรมดา -> PUA
  - ใช้อัลกอริทึม Greedy Longest Match First ในการแปลง (มีตัวอย่างโค้ดใน pua_converter.py)
  - ตรวจสอบว่าแท็ก <...> ไม่ถูกนำไปแปลงเป็น PUA โดยแยกแท็กออกมาก่อนแปลงเสมอ

[✓ Checklist 3: ตรวจสอบ String Pointer & Null Terminator]
  - ทุกสตริงในไฟล์ .dat ต้องมีไบต์ \x00 คั่นเสมอ
  - ค่า Offset Pointer ใน Record Table ต้องไม่ชี้เกินขนาดไฟล์ (No Out of bounds)
  - Record Descriptor ต้องนับขนาดตรงตามความยาวไบต์จริงของ UTF-8

[✓ Checklist 4: ตรวจสอบ FAFULLFS Alignment & Checksum]
  - ทุกไฟล์ย่อยใน data.dat และ misc_1_00.dat ต้องมี Offset ที่หาร 512 ลงตัว (Offset % 512 == 0)
  - รายการใน TOC ต้องเรียงตาม Hash Ascending Order
  - misc_1_00.dat ต้องมีขนาดเท่ากับ 166,815,977 bytes พอดี

หมวดที่ 4: เครื่องมือที่แนบมาให้ในโฟลเดอร์ '00_เครื่องมือและสคริปต์ตรวจสอบ'

1. pua_converter.py:
   - โค้ด Python ตัวอย่างที่สมบูรณ์สำหรับแปลงภาษาไทยปกติ -> PUA (และ PUA -> ปกติ)
   - มีระบบกันแท็ก <cmd ...>, <color ...> ไม่ให้ถูกตัดช่องว่างหรือเสียหาย
   - โปรแกรมเมอร์สามารถ import คลาส PUAConverter ไปใช้ในโค้ดของตนเองได้ทันที

2. validate_tags.py:
   - สคริปต์สำหรับรันสแกนตรวจสอบความผิดปกติของแท็กในทุกโฟลเดอร์ CSV
   - ช่วยตรวจจับว่ามีแท็ก <cmd...> ใดที่ช่องว่างหาย หรือวงเล็บเปิดปิดไม่เท่ากัน

3. quickbms_4gb_files.exe และ nis_fafullfs.bms / fafullfs.bms:
   - เครื่องมือมาตรฐานสำหรับ Unpack และ Reimport ไฟล์ Container FAFULLFS ดั้งเดิม
