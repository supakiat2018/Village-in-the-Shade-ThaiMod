# คู่มือและสเปกทางเทคนิคสำหรับโปรแกรมเมอร์ (Technical Specification)
## โครงการ: ม็อดภาษาไทยเกม Village in the Shade (PC Steam v1.30)
## ภารกิจ: แก้ไขไฟล์ `string.dat` เพื่อป้องกันเกมแครช / ค้างหน้า Now Loading

---

### 1. สรุปปัญหาและสภาพแวดล้อมระบบ (Problem Summary)
* **ตัวเกม:** *Village in the Shade* เวอร์ชัน **v1.30** (64-bit DirectX 11, รันผ่าน `village.exe`)
* **ระบบม็อดเดิม:** มีการใช้ `text_dump.dll` ฉีดเข้าเกมเพื่อทำหน้าที่ 2 อย่าง:
  1. **VFS Override:** ดักจับการเปิดไฟล์ `data/database/*.dat` และสลับไปอ่านไฟล์ภายนอกจาก `Mods\TextDump\dat\*.dat`
  2. **String Hooking:** ดักจับฟังก์ชันเรนเดอร์ข้อความ (`putStr`) เพื่อสลับข้อความภาษาญี่ปุ่น/อังกฤษ ไปเป็นข้อความภาษาไทย PUA แบบเรียลไทม์จากไฟล์ `Mods\TextDump\translation.txt`
* **สาเหตุของปัญหาใน v1.30:**
  * ตัวเกม `village.exe` มีการจองหน่วยความจำขนาดคงที่ (Fixed-size static buffer) สำหรับโหลดไฟล์ `data/database/string.dat`
  * ไฟล์ต้นฉบับสะอาด v1.30 มีขนาด **118,417 ไบต์** (408 เรคคอร์ด)
  * หากฉีดคำแปลภาษาไทย PUA ลงใน `string.dat` ครบทุกช่อง (Direct Injection) ไฟล์จะบวมเป็น **135,535 – 136,009 ไบต์** ทำให้หน่วยความจำล้น เกิดบั๊ก Access Violation แครชทันที (`0xC0000005`)
  * หากขนาดไฟล์ไม่สอดคล้องกับการอ่านแบบ Asynchronous VFS หรือพอยน์เตอร์ในเรคคอร์ดไม่ถูกต้อง ตัวเกมจะค้างที่หน้าจอ **"Now Loading..."** ตลอดเวลา

---

### 2. สูตรสำเร็จดั้งเดิมที่ใช้ได้จริงในเวอร์ชัน v1.20 (Proven Hybrid Formula)
ในเวอร์ชัน v1.20 เดิม (ไฟล์ `string_v120_proven_hybrid_97kb.dat` ที่แนบมา):
1. **คุมขนาดไฟล์ให้อยู่ที่ 97,774 ไบต์** (ต่ำกว่าขีดจำกัดหน่วยความจำ):
   * **ภาษาไทย PUA ฉีดตรงเฉพาะ 51 แถว:** เป็นแถวที่มีโค้ดระบบควบคุม เช่น `<value 1>`, `<cmd CMD_OK>`, `<br>`, `<c blue>`, รูปแบบวันที่ (`STR_ID_DATE_FORMAT`), วันในสัปดาห์, และชื่อสิ่งปลูกสร้าง
   * **สลับเป็นภาษาอังกฤษสั้น ๆ 344 แถว:** เช่น `Yes`, `No`, `Would you like to save?` แทนภาษาญี่ปุ่นเดิม เพื่อไม่ให้ Blob ข้อความบวม
   * **คงช่องว่างไว้ 7 แถว:** สำหรับ ID ที่เป็นสล็อตว่างเดิม
2. **ใช้ `translation.txt` แปลงอังกฤษเป็นไทย:**
   * ข้อความภาษาอังกฤษ 344 แถวข้างต้น จะถูกดักจับโดย `text_dump.dll` ผ่านไฟล์ `translation.txt` แล้วแสดงผลบนหน้าจอเป็นภาษาไทย PUA 100%

### 3. โครงสร้างไบนารีของไฟล์ `string.dat` (Binary Specification)

#### A. โครงสร้าง Header (12 ไบต์แรก)
```c
struct StringDatHeader {
    uint32_t record_count; // v1.30 = 408 (v1.20 = 402)
    uint32_t payload_sum;  // record_count * 88 (v1.30 = 35904)
    uint32_t blob_size;    // ขนาดของ String Blob ส่วนท้าย (ไบต์)
};
```

#### B. โครงสร้างตารางเรคคอร์ด (Record Table)
* จำนวนเรคคอร์ด: 408 เรคคอร์ด
* ขนาดต่อเรคคอร์ด (Stride): **92 ไบต์** ประกอบด้วย:
  * 4 ไบต์แรก: ขนาด Payload = 88 (`0x58000000`)
  * 88 ไบต์ถัดมา: อาเรย์ `uint32_t[22]` รายละเอียดฟิลด์ดังนี้:

| Index ใน uint32 | ไบต์ออฟเซตในเรคคอร์ด | ความหมาย |
|---|---|---|
| `u32[0]` | `+0` | ขนาดข้อมูล Payload = 88 ไบต์ |
| `u32[1]` | `+4` | Record ID (เช่น 1000..1407) |
| `u32[2]` | `+8` | Unknown / Flags (ค่าปกติคือ 0) |
| `u32[3], u32[4]` | `+12, +16` | Slot 0: **Key** (Offset ใน Blob, Length) |
| `u32[5], u32[6]` | `+20, +24` | Slot 1: **Japanese / Active String** (Offset ใน Blob, Length) |
| `u32[7], u32[8]` | `+28, +32` | Slot 2: **English (EN)** (Offset ใน Blob, Length) |
| `u32[9], u32[10]` | `+36, +40` | Slot 3: French (FR) |
| `u32[11], u32[12]` | `+44, +48` | Slot 4: Spanish (ES) |
| `u32[13], u32[14]` | `+52, +56` | Slot 5: จีนตัวเต็ม (ZH-TW) |
| `u32[15], u32[16]` | `+60, +64` | Slot 6: เกาหลี (KO) |
| `u32[17], u32[18]` | `+68, +72` | Slot 7: จีนตัวย่อ (ZH-CN) |
| `u32[19]..u32[22]` | `+76..+88` | สล็อตสำรอง (ค่าเป็น 0) |

#### C. โครงสร้าง String Blob
* เริ่มต้นที่ออฟเซตไบต์: `12 + (record_count * 92)` (สำหรับ v1.30 คือไบต์ที่ **37,548**)
* เก็บสตริง UTF-8 พร้อม null-terminator (`\0`)
* ออฟเซตของสตริงในแต่ละสล็อตจะอ้างอิงนับจากจุดเริ่มต้นของ String Blob นี้ (0-based)

### 4. รายการไฟล์ที่จัดเตรียมไว้ให้ในโฟลเดอร์นี้

1. **`string_original_v130.dat`** (118,417 ไบต์)
   * ไฟล์ต้นฉบับสะอาดแท้จากตัวเกม v1.30 มีโครงสร้าง 408 เรคคอร์ดครบถ้วน
2. **`string_v120_proven_hybrid_97kb.dat`** (97,774 ไบต์)
   * ไฟล์ตัวอย่างเวอร์ชัน v1.20 ที่ผ่านการทดสอบว่าเล่นได้ 100% ไม่แครช สามารถนำมาเปรียบเทียบดูโครงสร้างพอยน์เตอร์ได้ทันที
3. **`string_pc_v130_extracted.csv`** (127,448 ไบต์)
   * ตารางคำแปลครบ 408 แถว มีคอลัมน์: `Index`, `ID`, `Key`, `ต้นฉบับ_JP`, `EN`, `คำแปลไทย`, `Thai_PUA`
4. **`translation.txt`** (1,005,134 ไบต์)
   * ดิกชันนารีคำแปลที่ `text_dump.dll` ใช้อ่านเพื่อสลับข้อความบนหน้าจอ
5. **`text_dump.dll`** (151,552 ไบต์)
   * ตัวม็อด DLL ที่ติดตั้งอยู่ในเครื่อง
6. **`Mapping.json`** (46,646 ไบต์)
   * ตารางแปลงตัวอักษรไทยเป็นรหัส Private Use Area (PUA) สำหรับฟอนต์เกม

### 5. แนวทางการแก้ปัญหาที่แนะนำสำหรับโปรแกรมเมอร์

1. **แนวทางที่ 1 (Recommended - Rebuild Compact v1.30):**
   * สร้างไฟล์ `string.dat` ขนาด ~97KB – 118KB สำหรับ v1.30
   * รักษา Record Table 408 เรคคอร์ด
   * ในแต่ละเรคคอร์ด:
     * หากเป็นแถวที่มีแท็กระบบ (`<value>`, `<cmd>`, `<br>`, `<c>`, dates) ให้ชี้ Slot 1 ไปยังคำแปล `Thai_PUA`
     * หากเป็นแถวข้อความ UI ทั่วไป ให้ชี้ Slot 1 ไปยังข้อความภาษาอังกฤษ `EN` (ซึ่งมีคู่แปลภาษาไทยรออยู่ใน `translation.txt`)
     * นำเฉพาะ Key, สตริงภาษาไทยแท็ก, และสตริงภาษาอังกฤษมาสร้าง Blob ส่วนท้าย
   * เมื่อรันเกม: ตัวเกมจะโหลดไฟล์ได้อย่างราบรื่น ไม่ล้นบัฟเฟอร์ และ `text_dump.dll` จะแปลข้อความ UI ที่เหลือเป็นภาษาไทยให้เองอัตโนมัติ

2. **แนวทางที่ 2 (In-Place Translation Injection with Zero Size Diff):**
   * หากโปรแกรมเมอร์ต้องการขจัด `translation.txt` และฉีดไทย 100%: สามารถเขียนตัวจัดสรรสตริง (String Packer) แบบคอมแพกต์ ตัดภาษาอื่นๆ (FR, ES, KO, ZH) ที่ไม่ได้ใช้งานในเครื่องออก แล้วนำพื้นที่ว่างมาบรรจุภาษาไทย PUA ให้อยู่ในขนาดรวมไม่เกิน 118,417 ไบต์ เท่ากับไฟล์ต้นฉบับเดิมเป๊ะ (Zero Difference) ตัวเกมจะไม่มีทางแครชแน่นอน
